## Why
The installed iPhone app has its own storage and does not see saves made in the Safari tab. Players need to move progress between devices, and have an insurance against the phone clearing stored data.

## Do
1. **Format.** One JSON file, named `lazy-flight-save-YYYY-MM-DD.json`, made of: `format` (a constant like "lazy-flight-save", with its own `formatVersion`), `appVersion` if available, `exportedAt` (date), `save` (the exact current save content as `lazy-freight.save` holds it, including `saveVersion` and `universeVersion`), `sound` (content of `lazy-freight.sound`, optional), `summary` (credits, ships, ranks, explorer discoveries: for showing to the player before an import), and `checksum` (a hash of the rest, so damaged or edited files are noticed). Same data also as a single TEXT string (for copy/paste on phones where files are awkward): compact and safe to paste (no line breaks needed; base64 or the same JSON, your choice, say which).
2. **Export API** in `src/save`: `exportSaveFile(storage)` returns `{ filename, json, text, summary }` from what is in storage right now (and does not change anything). Works even when the game is mid-trip (export what the autosave holds; say in the report how a fresh export of the live state is obtained: probably flush the autosave first).
3. **Import API:** `inspectImport(textOrJson)` returns either `{ ok: true, summary, warnings }` or `{ ok: false, reason }` (plain, friendly text) WITHOUT changing anything: it checks the format name, size limit (say your limit), JSON validity, checksum, too-new `formatVersion`/`saveVersion`/`universeVersion` (refused: "this save is from a newer version, update the game first"), and that the save passes the normal repair path. `applyImport(storage, textOrJson)` then writes it: FIRST copies the current save to a backup key (one level of undo, e.g. `lazy-freight.save.beforeimport`, plus its sound settings), then writes the imported save through the existing load and migration path (universe v1 to v2 move + refund, pre-F1, pre-4g, and every older version) so nothing new can crash. `undoImport(storage)` restores the backup (and can itself be undone once, or say clearly that it cannot). A refused or failed import leaves the current save untouched.
4. **After import the game must be reloaded cleanly:** return a flag so the UI can reload the page (the safest way to start with fresh state). Make sure the in-memory game cannot overwrite the imported save with its old state (autosave order!). Prove it with a test.
5. **Debug page:** add to `/game-debug.html` a small "Save file" section: Export (shows the text and offers the file), Import (paste box and file chooser), shows the summary or the refusal, Undo. Real screens are Agent 5's job (P3).
6. **Tests (through the WHOLE load path, a past crash slipped through unit tests):** round trip (export, wipe storage, import, state identical including explored lists, liveries, ships, outposts and prices); every old save version imports (v1 universe, pre-F1, pre-4g) and the game loads it; corrupt file, wrong format name, edited file (bad checksum), truncated text, empty, huge file, too-new version: all refused with plain text and storage unchanged; backup and undo; two imports in a row; sound settings carried; unknown extra fields tolerated or dropped safely; the autosave does not overwrite an import. `npm run check` green; Actions green.
7. **Privacy and safety:** the file contains only game data. No email, no device info. Never execute anything from a file. Escape all text shown.
