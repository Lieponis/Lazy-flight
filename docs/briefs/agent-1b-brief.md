You are Agent 1 (Setup / Infrastructure). Work on the CURRENT `main` (never an old zip). Read first: docs/WHERE-TO-LOOK.md, docs/status.md, docs/ROADMAP-offline-app.md (the whole plan, hard rules and test workflow: source of truth), docs/report-agent-1.md, docs/report-agent-6a.md (saving), README.md. ## Goal
Andy can install the live game on his iPhone (and Android) from the browser, open it from the home screen, and play it fully offline after one online visit. Updates never break it or the save.

## Facts about this project
- Vite 8, `base: "./"` in vite.config.ts (relative paths, works under /Lazy-flight/ on GitHub Pages). Five HTML pages are built: index.html (the game) plus debug.html, game-debug.html, models.html, planets.html (developer pages). No `public/` folder exists yet.
- Publishing: .github/workflows/deploy.yml on main; .github/workflows/check.yml on other branches (never publishes).
- Saves in localStorage keys `lazy-freight.*` (do not change). Sound starts on the first user tap (keep).

## Do
1. **Manifest** (`manifest.webmanifest`): name "LAZY FLIGHT", short name "Lazy Flight", standalone or fullscreen display, any orientation, theme/background colours from the game's dark space look, `scope` and `start_url` correct for a GitHub Pages sub-folder (relative to the manifest), icons. Link it and add the iPhone tags (apple-touch-icon, apple-mobile-web-app-capable, status bar style, title) in index.html only.
2. **Icons:** simple PLACEHOLDER icons (192, 512, maskable 512, 180 Apple) made from the game's own look (e.g. a flat planet on dark space), generated by a script or drawn in code so no heavy tools are needed. The real icon art is stage P5 (Agent 7): make the icon files easy to replace (one folder, documented).
3. **Service worker** (`sw.js`, registered only in the game page `index.html`, only on https or localhost):
   - Precaches EVERY file the game needs to run (index.html, all hashed JS/CSS/asset files, icons, manifest, fonts, anything loaded at runtime including lazy chunks). The file list and a version id are generated at BUILD time (a small Vite plugin or post-build script); never a hand-kept list. Add a build check that fails if a file the game imports is missing from the list.
   - Cache-first for game files, with the cache name containing the build version. On activate delete old caches only after the new one is complete.
   - Navigation requests fall back to the cached index.html. If the cache is empty and there is no network, show a friendly game-styled offline page (not the browser's error page).
   - Developer pages (debug.html, game-debug.html, models.html, planets.html) are NOT precached and not controlled by the service worker (online only); say how you did it.
   - No analytics, no network calls to other sites.
4. **Update flow (most important for safety):** a new version downloads in the background into a NEW cache; the old version keeps running and serving until the new cache is complete; the switch happens only at app launch, or when the player taps "New version ready, tap to refresh" (a small note, wording in the game's friendly tone, styled like the other notes; ask Agent 5-style options only if you need a look decision, otherwise reuse the existing note style). Never swap files in the middle of a trip or while the save is being written. Old and new files must never be mixed (a page from version A must not load a script from version B).
5. **Kill switch:** a bad service worker can lock phones on a broken game. Provide a documented, tested way to retire it: a `sw.js` that unregisters itself and clears the caches, plus the steps in README (plain language) for how Andy or the Lead would publish it.
6. **Plain-language README section:** how to install on iPhone and Android, how offline works, how to update, how to remove, and the kill switch steps.
7. **Tests:** pure helper tests (cache list generation, version naming, URL matching of what is precached vs not); a built-output check (all needed files listed, manifest valid, icons exist with the right sizes); keep `npm run check` green. The full headless offline test suite is stage P4 (Agent 6): do NOT build it, but run a quick manual headless check (load online, go offline, reload) with Playwright if it is available in your workspace and report honestly what you could not verify.
8. **Deploy:** work on a branch (the branch check runs `npm run check`), then merge to `main` only when the check is green and Andy agrees. After the merge, confirm the Actions "Build and publish" run is green and the live site still loads in a normal (non-installed) browser tab.

## Allowed / not allowed
Allowed: index.html (head tags, registration snippet), a new `public/` folder (manifest, icons, offline page), `sw.js` and its build plugin/script, vite.config.ts, package.json scripts, workflows only if needed (tell the Lead why), tests, README, docs. Not allowed: src/universe, src/game, src/save, src/render, src/ui (except the one small "new version ready" note: put the smallest possible code in a new file under src/ui or src/main.ts and say exactly what you touched), changing save keys, new features.
